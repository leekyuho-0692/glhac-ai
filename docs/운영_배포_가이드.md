# GL-HAC 운영·배포 가이드

가비아 서버에서 GL-HAC 을 운영하는 사람을 위한 문서입니다.
**무엇을 어떻게 하는지**와 **잘못됐을 때 어떻게 되돌리는지**를 담았습니다.

마지막 확인 2026-09-12.

---

## 1. 지금 무엇이 어디서 도는가

```
가비아 서버  1.201.116.174  (Rocky 8 · 4코어 · 31GB · KST)

  glhac.co.kr   할랄 인증 시스템   nginx → 127.0.0.1:8800 (glhac-app)
  glhac.com     홈페이지·게시판     nginx → /var/www/glhac-home (정적)
```

두 도메인은 **서로 다른 사이트**지만 데이터는 한 곳(`glhac-app`)을 씁니다.
홈페이지 게시판도 `glhac.co.kr` 의 API 를 부릅니다 — 그래서 CORS 허용이 걸려 있습니다.

| 무엇 | 어디 |
|---|---|
| 백엔드 코드 | `/opt/glhac/app` |
| 설정(키 포함) | `/opt/glhac/.env` — 권한 600 |
| 데이터베이스 | `/var/lib/glhac/glhac_v3.db` (85MB) |
| 홈페이지 | `/var/www/glhac-home` |
| 자동 백업 | `/var/backups/glhac/` |
| OCR 모델 | `/home/rocky/.paddlex` (98MB) |
| nginx 설정 | `/etc/nginx/conf.d/glhac.conf` · `glhac-com.conf` |

**서류 파일은 디스크가 아니라 DB 안에 있습니다**(`document_asset.content_b64`).
DB 만 백업하면 서류도 함께 백업됩니다 — 별도 파일 백업이 필요 없습니다.

## 3. 배포하는 법

### 방법 A — GitHub 에서 (권장)

저장소 → **Actions** → **Deploy (가비아)** → **Run workflow**
→ 입력칸에 `deploy` 를 적고 실행.

`deploy` 를 적어야만 도는 이유는, 실수로 눌러 배포되는 일을 막기 위해서입니다.
백엔드는 **테스트가 통과해야 배포**합니다 — 깨진 코드는 서버에 올라가지 않습니다.

### 방법 B — 내 컴퓨터에서

```bash
git clone https://github.com/leekyuho-0692/glhac-ai.git
cd glhac-ai
bash scripts/deploy.sh                # 배포
bash scripts/deploy.sh --dry-run      # 무엇이 바뀌는지만 보기
bash scripts/deploy.sh --rollback     # 직전 백업으로 되돌리기
```

홈페이지(`glhac-web`)도 같은 방식입니다.

SSH 키가 기본 위치(`~/Downloads/SSH_KeyPair-260908134815.pem`)에 없으면
`GLHAC_SSH_KEY=/경로/키.pem` 으로 알려 주세요.

### 배포가 실제로 하는 일

```
백업 → 전송 → 소유권·SELinux 라벨 → 서비스 재기동 → 헬스체크 → 공개 URL 확인
                                                      ↓ 실패하면
                                              직전 백업으로 자동 복구
```

**헬스체크가 통과해야 끝난 것으로 봅니다.** 실패하면 그 자리에서 되돌리고
서버 로그 마지막 줄을 보여 줍니다.

## 4. 잘 됐는지 확인하는 법

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://glhac.co.kr/ui/
curl -s -o /dev/null -w '%{http_code}\n' https://glhac.com/
curl -s -o /dev/null -w '%{http_code}\n' https://glhac.com/board/
```

셋 다 `200` 이어야 합니다.

AI 기능이 살아 있는지는 이렇게 봅니다.

```bash
TOK=$(curl -s -X POST https://glhac.co.kr/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"비밀번호"}' | python3 -c "import json,sys;print(json.load(sys.stdin)['token'])")

curl -s https://glhac.co.kr/system/capabilities -H "Authorization: Bearer $TOK"
```

`"mode": "full"` 이면 정상입니다.
`"partial"` 이면 AI 일부가 꺼진 상태이고, 응답 안에 **무엇이 안 되고 대신 무엇을
하면 되는지** 적혀 있습니다. 시스템은 멈추지 않고 수기 모드로 계속 돕니다.

---

## 5. 되돌리기

배포 후 문제가 보이면 **한 줄**입니다.

```bash
bash scripts/deploy.sh --rollback
```

직전 백업(코드)으로 돌아가고 서비스를 다시 띄운 뒤 헬스체크까지 합니다.
백업은 서버 `/opt/` 에 최근 10개가 남아 있습니다.

## 6. 데이터 백업과 복구

### 자동 백업

**매일 새벽 3시(KST)** 에 돕니다. 85MB → 53MB 로 압축되고 4초쯤 걸립니다.
14일치를 보관합니다.

```bash
sudo systemctl list-timers glhac-backup.timer   # 다음 실행 시각
sudo tail -20 /var/log/glhac-backup.log         # 최근 기록
sudo ls -lh /var/backups/glhac/                 # 보관 중인 백업
```

그냥 복사하지 않고 `sqlite3 .backup` 을 씁니다 — DB 가 WAL 모드라 앱이 쓰는 중에
파일만 복사하면 **복구할 때 깨진 DB 가 나옵니다**. 뜬 뒤에는 무결성 검사와
내용 확인(케이스가 0건이면 실패 처리)까지 합니다.

### 지금 당장 한 번 더 뜨기

```bash
sudo /usr/local/bin/glhac-backup.sh
```

### 복구

```bash
# 1) 풀고 확인 — 'ok' 가 나와야 한다
gunzip -c /var/backups/glhac/glhac_v3-YYYYMMDD-HHMMSS.db.gz > /tmp/r.db
sqlite3 /tmp/r.db "PRAGMA integrity_check"
sqlite3 /tmp/r.db "SELECT COUNT(*) FROM case_application"

# 2) 바꿔치기
sudo systemctl stop glhac-app
sudo cp /var/lib/glhac/glhac_v3.db /var/lib/glhac/glhac_v3.db.before-restore
sudo cp /tmp/r.db /var/lib/glhac/glhac_v3.db
sudo chown rocky:rocky /var/lib/glhac/glhac_v3.db
sudo systemctl start glhac-app

# 3) 확인
curl -s -o /dev/null -w '%{http_code}\n' https://glhac.co.kr/ui/
```

**바꿔치기 전에 지금 DB 를 따로 복사해 두세요.** 복구본이 예상과 다를 수 있습니다.

```bash

```

## 8. 겪었던 문제들

실제로 한 번씩 겪은 것들입니다. 같은 증상이 보이면 여기부터 보세요.

### 화면을 고쳤는데 그대로다

`/assets/` 는 **1년 immutable 캐시**입니다. 번들 내용만 바꾸고 파일명을 그대로
두면 이미 방문한 브라우저가 옛 파일을 계속 씁니다.

→ 파일명을 바꾸고 `index.html` 의 참조도 함께 고치세요.
배포 스크립트가 이 경우를 **배포 전에 막습니다.**

HTML 자체는 `no-cache` 라 바로 반영됩니다(`/` 와 `/board/` 둘 다).

### 배포 후 서비스가 안 뜬다

소유권을 `root` 로 바꾸면 앱이 파일을 못 읽습니다. 서비스는 `rocky` 로 돕니다.

```bash
sudo chown -R rocky:rocky /opt/glhac/app
sudo systemctl restart glhac-app
```

### 홈페이지가 403 이다

SELinux 라벨이 빠진 것입니다.

```bash
sudo restorecon -R /var/www/glhac-home
```

### OCR 이 안 된다

서버 CPU 빌드에서 oneDNN 가속 경로가 터집니다. 꺼 두었습니다(기본값).
혹시 `GLHAC_OCR_MKLDNN=1` 이 들어가 있다면 빼세요.

`"ocr": {"installed": false}` 로 나오면 패키지가 빠진 것입니다.

```bash
sudo -u rocky /opt/glhac/.venv/bin/pip install 'paddlepaddle==3.3.1' 'paddleocr==3.7.0'
sudo dnf install -y mesa-libGL glib2      # libGL 없으면 임포트부터 실패한다
sudo systemctl restart glhac-app
```

### 게시판에 글이 안 써진다

도배 차단이 같은 IP 에서 **시간당 3건**으로 잡혀 있습니다.
행사처럼 한 회선에서 여럿이 쓰는 자리면 잠시 올리세요.

```bash
sudo sed -i 's/^GLHAC_BOARD_RATE_MAX=.*/GLHAC_BOARD_RATE_MAX=50/' /opt/glhac/.env
sudo systemctl restart glhac-app
# 끝나면 3 으로 되돌릴 것
```

| 언제 | 무엇 |

| 배포할 때마다 | 공개 URL 3곳이 200 인지 |

| 수시 | 디스크 여유(현재 490GB 남음) |

```bash
sudo certbot certificates | grep -E "Certificate Name|Expiry"
df -h /
```

**복구 시험을 권합니다.** 백업은 복구해 봐야 백업입니다 —
`/tmp` 에 풀어 건수만 세어 봐도 충분합니다.

## 10. 지금 알려진 약점

정리해 두는 편이 안전한 것들입니다.

- **데모 계정이 열려 있습니다.** `admin/admin`, `consultant1/pw` 등이
  인터넷에서 그대로 들어갑니다. 실제 업체 서류가 들어 있으므로
  비밀번호를 바꾸거나 접속 IP 를 제한하세요.
- **백업이 같은 서버에만 있습니다.** 서버 자체가 사라지면 백업도 함께 사라집니다.
  중요해지면 외부(NAS·클라우드)로 한 벌 더 빼야 합니다.
- **맥에 옛 시스템이 아직 돕니다.** 별도 DB 를 쓰므로, 어느 쪽이 정본인지
  헷갈릴 수 있습니다.
