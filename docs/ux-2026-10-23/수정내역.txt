수정 내용
1. 기업 정보 임시저장과 신청 제출 전에 실제 프로필 저장 결과를 확인한다. 실패 시 다음 요청·성공 표시를 중단한다.
2. 입력 중인 기업 정보와 품목, 할랄 관리 조직을 화면 이동·언어 전환·비동기 화면 갱신 동안 보존한다. 계정과 신청 건별로 분리한다. 저장하지 않은 변경이 있으면 브라우저를 떠나거나 로그아웃할 때 경고한다.
3. 저장 범위를 ‘기업 정보 임시저장’으로 명시한다. 품목·공장·조직은 해당 버튼으로 등록하며, 미등록 품목이나 미저장 조직 변경이 있으면 최종 신청을 막고 안내한다.
4. doc-checklist 객체의 checklist 배열을 사용한다. 적용 제외 항목은 필수 분모에서 제외하고, 잘못된 응답을 0/0으로 표시하지 않는다.
5. PPH는 현재 배정된 건만 목록과 상세에 표시한다. 조직이 다른 배정도 허용하며 재배정 후 이전 담당자는 목록·상세·검증에서 제외한다. 관리자·운영자 목록도 기존 기관 권한 정책을 사용한다.
6. 배정 순서는 새 assigned_at 컬럼으로 정한다. 기존 경량 마이그레이션이 컬럼을 추가한다. 과거 시각이 없는 행은 기존 assignment_id 순서를 유지하므로 과거 복수 배정의 실제 순서는 복원할 수 없다. 새 배정부터 시각 기준으로 일치한다.
7. 원재료 데이터가 없거나 검토되지 않은 경우, 완료된 심사 일정이 없는 경우 준비도 세부값을 null/미평가로 구분한다. v4는 전체 평가 진행 중으로 표시한다. 숫자 readiness는 확인된 영역의 가중 기여분만 합산한다. ready/ok 표기도 일치시켰다.
8. API에서 받은 회사명·제품명·담당자명·자유 입력은 UI 사전 번역에서 보호한다. 새 안내 문구는 영어·인도네시아어 번역을 추가했다.
9. 기업 홈 맨 위에 단계별 ‘지금 할 일’과 바로가기 배치. 중복 11단계 여정 제거, 기존 8단계 유지. 철회·원재료 정리는 접어서 제공한다.
10. 기업 기본 정보를 신청 화면 위로 이동하고 추가 기업 정보는 펼침 방식으로 변경했다. 식품 신청에서 차량·세척 패널을 숨겼다. 고객 화면의 profile_ext/members 표현을 바꿨다.
11. 계약·견적·청구가 없는 경우 한 개의 대기 안내를 표시한다. 계약 없는 0원과 기본 7일 기한을 표시하지 않는다.
12. 감독자·운영자 역할명을 구분하고 제출 전 건에 반려 버튼을 숨겼다. 기존 운영자·관리자 메뉴 권한은 유지했다.
13. 변경된 JS에 버전 쿼리를 추가해 브라우저의 이전 스크립트 캐시가 수정 화면과 섞이지 않도록 했다.

배포 시 확인
운영 파일의 현재 버전이 분석 당시 스냅샷과 달라졌다면 먼저 패치 적용 검사를 다시 해야 한다.
운영 서비스 재시작과 DB 컬럼 추가가 포함되므로 운영 코드 및 DB 백업 후 적용한다. SQLite DB 백업은 WAL을 포함하는 backup API로 수행한다.
되돌릴 때 제품 파일을 복원하면 되고 추가된 nullable assigned_at 컬럼은 남겨도 기존 코드에 영향을 주지 않는다. 운영 데이터 수정/삭제는 이번 패치에 없다.

범위 및 한계
이번 수정은 재현된 오류와 기업 신청 화면의 주요 불편, 역할 표시를 해결했다. 컨설턴트·오디터의 기업별 통합 작업 공간 전체 재설계와 실제 고객 대상 사용성 측정은 별도 제품 개선 과제다.
입력 초안은 현재 탭 메모리에 보존한다. 강제 종료까지 복구하는 영속 자동저장은 아니다. 품목·공장·조직의 서버 저장은 각 등록 버튼으로 명시했다.
모든 인증·계약·입금·발급 상태를 끝까지 실행한 E2E 전수 검증은 아니다. 실제 고객 데이터와 운영 계정으로 시험하지 않았다.
지정된 cli-v2는 Port 1 API 인증 401로 실패하여 사용자 AGENTS 지침의 fallback에 따라 직접 수정했다.
