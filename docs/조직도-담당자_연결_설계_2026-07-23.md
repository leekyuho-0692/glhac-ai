## 2. 연결 핵심 원칙

> **신청 폼의 담당자 = 할랄 조직도(Struktur Organisasi Tim Manajemen Halal)의 데이터 원천(single source of truth).**

폼 담당자로 조직도 초안을 자동 생성하고, 나중에 실제 조직도 서류가 오면 이름을 교차검증한다.

### 폼 필드 → 조직도 역할 매핑
```
        [경영책임자 · Top Management]
        {responsible_person} (대표자/Direktur) ── 경영약속(komitmen halal)
                        │
        ┌───────────────┴───────────────┐
        │   할랄팀 · Tim Manajemen Halal   │
        └───────────────┬───────────────┘
     ┌──────────────────┼──────────────────┐
 [할랄감독자]         [PIC 담당자]         [CP 업무담당자]
 Penyelia Halal      실무 코디네이터        대외 연락
 {halal_supervisor}  {pic_name}/{pic_title} {cp_name}/{cp_title}
 + PenyeliaHalal[]
```

## 3. 설계 — 3단계 (누적)

### Level 1 (MVP) · 폼 → 조직도 초안 자동생성
- **변경점**: `index.html:7627`의 `AUTO_KEYS`에 `org_structure`(할랄팀 조직) 추가.
- manualBuilder가 폼 담당자(대표·할랄감독자·PIC·CP·PenyeliaHalal)에서 조직도를 **자동 렌더**. 사용자는 빈 조직도를 그리는 대신 자동 초안을 **보고 수정/보강**.
- 조직도 서류를 "새로 받는" 게 아니라 **폼에서 파생** → 제출 부담↓.
- **범위**: 프런트 중심. 암호화 컬럼(대표·할랄감독자)은 서버가 복호화해 내려주는 기존 폼 값 재사용(신규 노출 없음).

### Level 2 · 나중 받는 조직도 서류와 교차검증
- 조직도/`sjph_manual` 이미지 업로드 시 기존 OCR 경로(`mbOcrCaption`) 재사용 → OCR 텍스트에서 인물 이름 추출.
- 폼의 대표·할랄감독자·PIC와 **대조**, 불일치를 오디터 화면에 플래그:
  - 조직도엔 있으나 폼엔 없는 인물 / 폼엔 있으나 조직도에 없는 인물.
- CoA 측정값 자동반영과 동일 패턴(서류↔폼 정합성).
- **범위**: 백엔드 추출·대조 로직 + 오디터 화면 플래그 표시.

### Level 3 · 구조화된 할랄팀 모델 (별도 스프린트)
- 흩어진 담당자 필드를 `halal_org` 구조체로 정규화:
```json
profile_ext.halal_org = {
  "top_mgmt":  {"name": "", "title": ""},
  "penyelia":  [{"name": "", "cert_no": "", "status": ""}],   // PenyeliaHalal 연동
  "members":   [{"name": "", "title": "", "division": "", "role": "pic|cp|qc|produksi|gudang"}]
}
```
- 조직도 노드 = 이 구조 그대로. 심사·매뉴얼·CAR 전반에서 재사용.
- **주의**: 데이터 모델 변경 → 마이그레이션 필요. 기존 필드를 깨지 않고 `halal_org`를 우선 **파생 뷰**로 두는 게 안전.

---

## 4. 추천 & 트레이드오프
- **Level 1 + 2가 스윗스폿**: L1은 프런트만(백엔드 무변경 가능), L2는 기존 OCR 재사용 → 추가비용 적고 심사 실효성 큼.
- L3는 마이그레이션 동반이라 별도 스프린트 권장. `halal_org`는 파생 뷰 → 실테이블 순으로 단계 이행.
- **개인정보 주의**: `responsible_person`·`halal_supervisor`는 암호화 컬럼. 조직도 이미지를 외부 공유하면 개인정보 노출 → 심사용 내부 렌더로 한정.
